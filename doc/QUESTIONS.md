53. **Should the core opcodes be hand-written C at all?** About 27 opcodes (`SETUP_*`, `POP_BLOCK`, `LOAD_GLOBAL`, `LOAD_NAME`, `STORE_NAME`, `CALL_*`, `FOR_ITER`, `RETURN_VALUE`, `YIELD_VALUE`) are hand-written in `pycompiler.c` because they touch the frame, the block stack or calls, which Ni models itself. They are also what CPython changes most between versions (3.8 drops `SETUP_LOOP`, 3.11 drops the block stack). Options to weigh in the first simplification step (D135), by what is simplest to maintain: describe frame state (`f_globals`, `f_builtins`, `f_locals`) as vocabulary so those cases generate; derive the block-stack and call cases from ceval with Ni's frame model as the target; or keep a small hand layer and measure what each port costs it. Decide from the 3.8 port's measures (Tony, 2026-11-18).
