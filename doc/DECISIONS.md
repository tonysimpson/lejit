| D16 | 2026-11-16 | **Long-term aim:** a core with no coupling to Python, plus a meta-compiler that consumes any CPython 3.8+ source (3.7 for now) and generates the whole Python layer, including the bytecode compiler. | D17 | 2026-11-16 | **Target CPython 3.12+.** The generated bytecode compiler will consume `Python/bytecodes.c`. 3.7 is kept only as the existing reference implementation. | Owner. 3.12 has a machine-readable instruction definition; 3.8–3.11 would need `ceval.c` parsed. |
| D18 | 2026-11-16 | **3.7 baseline, time-boxed.** Build and run on 3.7, and fix only **core and backend** bugs (the `v_mem_mov` encodings, the 32-bit compare, stack alignment), since that code survives. Don't fix bugs in the translated layer (`binary_op1`, Py2-meaning opcodes, `"__builtin__"`): it will be regenerated, so note them and work around them in tests. Exception: a minimal fix (a few lines) is allowed when a translated-layer bug crashes the compiler and blocks testing of the core; record it in KNOWN_BUGS. Stop when simple int/float tests pass and nianalyser shows correct code. | It gives a test bed for the version-independent code and a reference output for generated code. |
| D19 | 2026-11-16 | **Start the meta-compiler simply, in stages.** 0: generate field descriptors and layouts (`DEF_FIELD` plus `static_assert`s) from the 3.12 headers. 1: token-level pattern rewriting of a small regular slice (float slots, some of `abstract.c`), compared with the hand-written `p*.c`. 2: add analysis only where rewriting demonstrably fails (run-time vs compile-time values, branches on run-time values, ownership). | Owner: the goal stays, but start with something simple that is known to work. |
| D20 | 2026-11-16 | **Simplest tool that works; no clang.** Start with plain token-level rewriting in Python (`cases_generator` for `bytecodes.c`). Move to pycparser with stub headers, or Coccinelle, only when the simple approach fails on real input. Log each failure in `METACOMPILER.md`. clang is the last resort. | Owner: start simple and document the options for later. clang would mean learning and teaching a lot of clang. |
| D21 | 2026-11-16 | **Guardrails as we go.** Every bug fix also adds the check that would have caught it: a test that fails without the fix (shown once with `tools/without_fix.sh <files> -- <test>`, which forces the rebuild), or an assertion at the site, or a tool check. Run `tools/check.sh` before every commit: it rebuilds, refuses a failed or stale build, and runs every suite. Existing guards: the respawn replay check (ALL_CHECKS, `dispatcher.c:respawn_check`, `796222d`), `setup.py` dependencies and option stamp, the staleness check, `check.py`'s orphan `@asm` check, `TEMP_PUSH_R`/`TEMP_POP_R` (B14), unify's run-time register check under `ALL_CHECKS` (B7), the `psyco_coding_pause` flags assert (B8). | Owner: "mistakes are easy to make, we should make sure we are adding guardrails as we go". A stale build hid a compile error, and a B7 test passed by luck. |
| D22 | 2026-11-16 | **CPython's own tests are a regression check, not a target.** `tests/cpython_tests.py` (50 modules, in `check.sh`) guards the baseline and, later, the regenerated translated layer. More modules may be added when cheap. | D23 | 2026-11-16 | **Compiled code borrows its globals; nothing may read them at compile time.** The globals dict is a compile-time constant but not owned (`vcompiler.c:PsycoObject_FromCode`, `ni_code_extra_t.entry_globals`), which breaks the cycle that kept code with its own globals alive (KNOWN_BUGS C14). This is safe only while compiled code uses the dict purely as an argument to run-time calls: a dead dict's address can be reused by a new dict, and old code then serves the new one. Anything that folds globals' contents at compile time (a cached LOAD_GLOBAL, generated code) must take its own owned reference, with a check that the value hasn't changed. On 3.12+ a dict watcher could drop code when its globals die (QUESTIONS 27). | Owner accepted (2026-11-16) | [read], [run] |
| D24 | 2026-11-16 | **Generated code is checked in, and `check.sh` fails if it is stale.** `ni/Objects/plongobject_gen.h` is written by `tools/metac/gen_long.py` from CPython's source. So building Ni needs no generator and no CPython source tree, a change to the generator shows as a diff of its output, and `tools/check.sh` reruns it with `--check` (CPython source at `NI_CPYTHON_SRC`, default the pyenv 3.7.17 tree). Generated files are never edited by hand. | `64f88e7` |
| D25 | 2026-11-16 | **LOAD_GLOBAL is cached as a constant behind the dicts' version tags.** With globals known at compile time, `pycompiler.c:load_global_cached` looks the name up while compiling and guards on `ma_version_tag` (PEP 509) of globals and builtins; a mismatch with the same object updates the expected tags, a real change respawns into a version that loads the name at run time. Satisfies D23's condition: the cache owns the value (and builtins), globals stays borrowed, and a dict at a reused address has a new tag. Two rules keep respawn correct, because a replay re-runs compilation with the dicts as they are then: nothing before a site's respawn point may depend on the dicts' contents, and each guarded site ends its block (`pr.split_after_global`). Costs: cached values live as long as the compiled code (constants are never released, `vcompiler.c:sk_release`), one never-freed 16-byte guard slot per compiled site, and a snapshot per site at compile time. Upstream did the same with dict-table internals (`9bd5834:c/Python/pycompiler.c:load_global`). On 3.12+ `ma_version_tag` is deprecated (PEP 699); dict watchers replace the check (QUESTIONS 29). `7a3a109` | Owner's plan (2026-11-16) | [read], [run] |
| D26 | 2026-11-17 | **The bytecode generator reads 3.12's instruction DSL, on 3.7 too.** `tools/metac/gen_ceval.py` takes instruction definitions in `Python/bytecodes.c` syntax, parsed by CPython's own parser (vendored from 3.12.9, `tools/metac/cases_generator/`), and writes `ni/Python/pycompiler_gen.h`. For the 3.7 baseline the input is `tools/metac/bytecodes37.c`, which describes 3.7's `ceval.c` cases in that syntax; on 3.12 it is upstream's `bytecodes.c`. So the part built and tested now (DSL to compile-time code) is the part that carries over, and a 3.7 front end that infers stack effects from `POP()`/`TOP()` sequences is never written. `bytecodes37.c` is hand-written, which edges towards the hand-written layer GOAL.md wants rid of; it is allowed because it describes CPython in CPython's format, is checked against 3.7 by the generator (TARGET exists, same C-API calls, `dis.stack_effect`), and is thrown away with the baseline. It must not grow Ni-specific content: anything Ni-specific belongs in the generator's vocabulary. | Owner (2026-11-17), after the 3.12 desk read | [run] |

| D28 | 2026-11-17 | **Debug with pointbreak, not gdb.** Crash and trace tools are pointbreak scripts in `tools/nianalyser` (`crash_report.py`, `dump_function.py`), hooked on Ni's code generator. What pointbreak lacks or makes awkward goes in `doc/pointbreak-journal.md`, as feedback for pointbreak (maintained separately; Ni never changes it). | Owner (2026-11-17) | — |
| D29 | 2026-11-17 | **Compile speed comes first; no IR.** Psyco compiles in one pass, with registers chosen as code is emitted. That makes the code dense, but compiling is cheap, so Ni can compile eagerly and respawn freely: a function that is compiled and then rarely called costs little. JITs with an IR pay much more per compile and must be cautious about what they compile. Tidying the backend boundary (locations behind a backend interface, so the calling convention and register allocator can change; ARCHITECTURE.md, Leaks to close) and trying other allocation policies is welcome. Every such change is measured against compile time as well as run time; when in doubt, choose compile speed and no IR. | Owner (2026-11-17): a feeling, not yet measured (QUESTIONS 35). | — |
| D30 | 2026-11-17 | **Attribute lookup is specialised on the type, and the compiled code keeps the descriptors it used** (A9, `d70e7f7`). `pobject.c:generic_getattr` follows `_PyObject_GenericGetAttrWithDict` at compile time for a known type, behind a per-site `tp_version_tag` guard; a change respawns into the generic call. Each descriptor it specialised on (function, property, member descriptor, class attribute) is held by the compiled code for good, as cached globals (D25) and promoted constants (F25) are: a replaced class keeps its old attributes alive while the code lives, and compiled code is never freed. Rejected: holding no reference and re-checking identity at run time (a load and a compare per access). Rule kept from D25: nothing before the guard may depend on the type's mutable state, so heap types always take the guarded path. | Owner (2026-11-17): merge as is. pyperformance 1.64× → 1.76×. | [run] |
| D31 | 2026-11-17 | **Instance attribute loads are inline on the class's shared keys (PEP 412), and decisions a replay must repeat may depend on one-way state through the block serial.** `pobject.c:instance_dict_get` checks that the instance dict uses the keys compiled in and loads the value at the name's index; the expected values are run-time loads from a per-site `keys_guard_t`, so the code is the same in a replay whatever the keys are then. The compiled code holds the keys for good (`dk_refcnt`), like D30's descriptors. Whether to emit the inline path at all depends on whether the class still has shared keys, which a replay may see differently; `keys_inline` makes it a function of the class and `codemanager.h:psyco_block_serial`, which a replay shares with its original compile, using the fact that CPython never restores dropped keys. Mirrors 3.7's `struct _dictkeysobject` (`ni_dictkeys_t`). Rejected: an always-failing check for classes without keys (one respawn per site, go +60% code); holding no reference to the keys (an address reused by other keys would pass the check). | PROFILE.md: instance dict lookups were 20–35% of richards, deltablue and raytrace. Owner asked for this (2026-11-17). |
| D32 | 2026-11-17 | **Respawn stubs are 15 bytes in pooled chunks, with one shared trampoline and their records on the heap** (`2f8d00f`). `dispatcher.c:psyco_new_stub` writes `mov r11, record; jmp psyco_stub_trampoline` into 4 KB chunks of code buffer memory, each closed at once so no buffer stays locked; the record (function, closure, `respawn_t`) is `PyMem_Malloc`'d and freed when `do_respawn` has compiled the branch. Coding pauses use the same stubs (`d51860c`): the record holds the `coding_pause_t`, freed by `do_resume_coding_body` once the jump is repointed; promotion stubs still use `psyco_call_code_builder`. The trampoline (`x64/iprocessor.c`) aligns the stack itself, since it can't know the depth at compile time. Rule: compiled code must not enter shared code with a `call` it never returns from (it costs every later `ret` a misprediction). Rejected: a 5-byte `call` with the record found by return address in a table (needs a lookup, and has the same `call` problem); stubs out of line at the end of each block (blocks have many exits). | CODE_SIZE.md: stubs were 46–52% of the code, and 1–4% of them ever fire. Code 37–44% smaller; speed and compile time unchanged. Pauses: a further 2–6% (go 1057 → 1006 KB), branch misses unchanged. Owner agreed the design (2026-11-17). |
| D33 | 2026-11-17 | **At merge points a counter has one form: a virtual int whose value may be known or run-time, and a known value may match a run-time one** (`1c61916`, `5e37663`). `dispatcher.c:canonical_int` rewrites a non-fixed constant small int (-5 to 256) or bool in a local as a virtual int with that value, in place, before comparing and freezing; `compatible_vinfo` lets the value word of a virtual int or bool that is a non-fixed constant partially match a run-time value (no reference, sign allowed), un-promoting it. Both depend only on the state and the snapshots, so a respawn replay, which starts from the rewritten snapshot and never crosses a merge point, sees the same thing. Only small ints and bools, so computing the virtual int gives back the same object; only locals, because LOAD_CONST's constants have no `SkFlagPyObj` to show they are objects. Rejected: rewriting stack slots and nested arrays (no way to tell an object from a raw word there); a known value of any kind matching a run-time one (that is option 3's cap, a policy for later). | CODE_SIZE.md option 2: go's `Board.useful` started 65 blocks at one merge point. go code 1057 → 426 KB, compile 13.1 → 3.0 ms; warm speed within ±1.2%. |
| D34 | 2026-11-17 | **Current phase: a robust 3.7 baseline with worthwhile performance improvements, before the 3.12 port and the meta-compiler** (GOAL.md). Work comes from `doc/BACKLOG.md`; each performance change is measured against speed, compile time and code size (D29), and its pattern recorded in PATTERNS.md. | Owner (2026-11-17). |
| D35 | 2026-11-17 | **Inline dict stores take their version tag from Ni's own counter, starting at 2^63** (STORES.md option 4). CPython 3.7's counter (`pydict_global_version`) is a `static` in `dictobject.c` that Ni can't reach. A tag only has to differ from that dict's earlier tags, and CPython's counter never reaches 2^63. Rejected: finding CPython's counter through libpython's symbol table (may be stripped; varies by build). | Owner (2026-11-17). |
| D36 | 2026-11-17 | **A METH_FASTCALL builtin without a meta is called directly through fixed-arity helpers, and a meta is registered only under the convention it was written for** (F13, `17b2a04`, `cec9770`). `pmethodobject.c:PsycoCFunction_CallFast` emits a call to `cimpl_fastN(meth, self, a0..aN-1)` (N ≤ 5, `psyco_generic_call`'s limit of seven arguments), which builds the C array on its own stack; more arguments or an unknown count pass the tuple's items. Keywords stay a residual `PyCFunction_Call`. `Psyco_DefineModuleFn` still refuses a meta whose `ml_flags` differ, but lists it (`ni._unregistered_metas()`, printed in checked builds, a `compile_bounds.py` failure). Rejected: a new `psyco_generic_call` argument kind that lays an input array out on the machine stack (backend work for no measurable gain over the helpers' extra copy); adapting a meta to another convention at the call (each meta's residual fallback calls the C function with its own convention, so every fallback would need rewriting, for no meta that fails on 3.7). | Residual FASTCALL calls were up to 1.25M per iteration (fannkuch). Instructions per warm iteration: fannkuch −6.8%, comprehensions −7%, deepcopy −20%, mdp −0.6%, pyflate −0.5%, others unchanged; code +0.3%, compile time unchanged within noise. |
| D37 | 2026-11-17 | **str is read inline only where its layout is known while compiling: a compact ASCII string at run time, or a compact constant of any kind; everything else is a C call on a respawned branch.** `punicodeobject.c` tests the PEP 393 state byte (ready, ascii, compact) and then reads the length and the byte; other kinds, subclasses (never compact) and strings not yet ready (length field 0) go to `cimpl_unicode_item`/`unicode_length`. The init checks the layout and stops Ni loudly if it differs. Rejected: specialising on the kind by promotion (one more dispatch per site for kinds that are rare in practice); assuming every str is ready (legacy-API strings exist in 3.7). | PROFILE.md (str and bytes): no benchmark here spends measurable time on str; bytes indexing is pyflate's largest string cost. `9abd6a3` [run] |
