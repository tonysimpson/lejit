# Decisions

Settled choices, with reasons. Don't reopen these without new evidence; add new ones at the bottom with a date.

| # | Date | Decision | Reason |
|---|---|---|---|
| D1 | 2026-11-16 | Keep Psyco's design (run/compile/virtual time, promotion, merge points, virtual objects) as the template for the JIT. | It was a proven JIT for CPython. The failure was maintainability, not the design. |
| D2 | 2026-11-16 | Fix maintainability by **generating** the compile-time CPython layer from CPython's C source with a meta-compiler. Don't follow PyPy, a tracing JIT or copy-and-patch. | Owner's thesis (see `GOAL.md`). Armin anticipated it in `ni/Python/pycompiler.h`. |
| D3 | 2026-11-16 | The current phase is research and classification, not new code. | We need to know what is core, translated, backend and obsolete before designing. |
| D4 | 2026-11-16 | **The source files are the source of truth.** Docs hold only what code can't say: goal, cross-file mechanisms, classification and judgement, history, references. There are no per-file prose summaries. | Summaries duplicate code and go out of date; an AI reads C quickly. |
| D5 | 2026-11-16 | ~~Every source file gets a templated header comment.~~ Superseded by D9. | |
| D6 | 2026-11-16 | `doc/MAP.md` is the coverage ledger: one row per file, with the commit it was reviewed at. | Guarantees every file was looked at, without per-file docs. |
| D7 | 2026-11-16 | Upstream Psyco reference is git `9bd5834` in this repo's own history. Nothing is vendored. | The full history is already here. |
| D8 | 2026-11-16 | Docs are local Markdown in `doc/`, in British English, with claims marked **[read]** or **[inferred]** and anchored to `file:function` rather than line numbers. | Owner preference; reliability for later readers. |
| D9 | 2026-11-16 | **Comments only where the code is complex.** Psyco's core, virtual-object, backend and translation files get a comment written for that file: what is non-obvious, the traps, known bugs. Simple files get no comment. Single-site bugs get a comment at the site, not a file header. No templated headers. | Owner's instruction: Psyco code is complex and needs it; other files don't. |
| D10 | 2026-11-16 | "Merge points on almost every instruction" (`ni/mergepoints.c`) was a **stop-gap**. Restore control-flow-based placement (upstream: joins only, delayed past light instructions, at most 170 instructions apart). **Done** in `27f066d` (no delaying). Step 2, inlining by upstream's rule, **done** in `085392a` with B6 fixed: tiny-function call loops 12–25% faster, 14% more code buffers on the smoke test. | Owner confirmed. It multiplies snapshots and disables inlining (history A2/A4). |
| D11 | 2026-11-16 | **Bring back compact objects** (fast instance attributes), keeping the old design but making it easier to understand. | Owner: "we need something like them". Main attribute optimisation (history: removed-files). |
| D12 | 2026-11-16 | **Compile everything on first call for now, deliberately**, until everything can be compiled. After that, compile only what would run faster compiled (a hotness or benefit policy replaces the placeholder in `ni/eval_hook.c`). | Owner: the eval hook is a placeholder; compiling everything exposes gaps. |
| D13 | 2026-11-16 | **Support floats, and bring back integers** through a virtual short-int value type, possibly separate i32 and i64 variants, that falls back to `PyLong` on overflow. **Started** in `fdbaa88`: virtual ints for + - * unary - and comparisons, following CPython's one-digit fast paths (no overflow check needed), which the owner chose over upstream's overflow-flag style (2026-11-16). // % / wait for backend support. | Owner. Upstream's virtual Py2 int (`pintobject.c`) is the model (history A5). |
| D14 | 2026-11-16 | **Supporting Python 3 `bytes` and `str` (PEP 393 unicode) is a goal.** The Py2 `pstringobject.c` virtual strings are the design reference, not the code to port as-is. | Owner. |
| D15 | 2026-11-16 | **Restore dead-local deletion** (upstream liveness analysis; history A3) together with D10. At each merge point, drop locals never read again before `psyco_compatible` compares states; keep upstream's opt-out for code using `locals()`/`vars()`/`eval()`/`exec()`. Restore the `CodeBuffer_Check` guard in `psyco_compatible` removed in `e1fd808`. **Done** in `458ef80`: a new 3.7 liveness pass in `mergepoints.c` (upstream's was tied to Py2 bytecode); no opt-out needed since C15 rejects such code. | Owner accepted the recommendation. More reuse of compiled code, smaller snapshots, earlier decrefs; cheap once merge points are only at joins. |
| D16 | 2026-11-16 | **Long-term aim:** a core with no coupling to Python, plus a meta-compiler that consumes any CPython 3.8+ source (3.7 for now) and generates the whole Python layer, including the bytecode compiler. When CPython makes an incompatible change, generation fails loudly and says why. See `GOAL.md`, Long-term aim. | Owner: it's a very high bar, but anything less stays unmaintainable. |
| D17 | 2026-11-16 | **Target CPython 3.12+.** The generated bytecode compiler will consume `Python/bytecodes.c`. 3.7 is kept only as the existing reference implementation. | Owner. 3.12 has a machine-readable instruction definition; 3.8–3.11 would need `ceval.c` parsed. |
| D18 | 2026-11-16 | **3.7 baseline, time-boxed.** Build and run on 3.7, and fix only **core and backend** bugs (the `v_mem_mov` encodings, the 32-bit compare, stack alignment), since that code survives. Don't fix bugs in the translated layer (`binary_op1`, Py2-meaning opcodes, `"__builtin__"`): it will be regenerated, so note them and work around them in tests. Exception: a minimal fix (a few lines) is allowed when a translated-layer bug crashes the compiler and blocks testing of the core; record it in KNOWN_BUGS. Stop when simple int/float tests pass and nianalyser shows correct code. | It gives a test bed for the version-independent code and a reference output for generated code. |
| D19 | 2026-11-16 | **Start the meta-compiler simply, in stages.** 0: generate field descriptors and layouts (`DEF_FIELD` plus `static_assert`s) from the 3.12 headers. 1: token-level pattern rewriting of a small regular slice (float slots, some of `abstract.c`), compared with the hand-written `p*.c`. 2: add analysis only where rewriting demonstrably fails (run-time vs compile-time values, branches on run-time values, ownership). | Owner: the goal stays, but start with something simple that is known to work. |
| D20 | 2026-11-16 | **Simplest tool that works; no clang.** Start with plain token-level rewriting in Python (`cases_generator` for `bytecodes.c`). Move to pycparser with stub headers, or Coccinelle, only when the simple approach fails on real input. Log each failure in `METACOMPILER.md`. clang is the last resort. | Owner: start simple and document the options for later. clang would mean learning and teaching a lot of clang. |
| D21 | 2026-11-16 | **Guardrails as we go.** Every bug fix also adds the check that would have caught it: a test that fails without the fix (shown once with `tools/without_fix.sh <files> -- <test>`, which forces the rebuild), or an assertion at the site, or a tool check. Run `tools/check.sh` before every commit: it rebuilds, refuses a failed or stale build, and runs every suite. Existing guards: `setup.py` dependencies and option stamp, the staleness check, `check.py`'s orphan `@asm` check, `TEMP_PUSH_R`/`TEMP_POP_R` (B14), unify's run-time register check under `ALL_CHECKS` (B7), the `psyco_coding_pause` flags assert (B8). | Owner: "mistakes are easy to make, we should make sure we are adding guardrails as we go". A stale build hid a compile error, and a B7 test passed by luck. |
| D22 | 2026-11-16 | **CPython's own tests are a regression check, not a target.** `tests/cpython_tests.py` (50 modules, in `check.sh`) guards the baseline and, later, the regenerated translated layer. More modules may be added when cheap. Core and backend bugs they find are fixed (D18); translated-layer bugs are logged in KNOWN_BUGS and fixed only when cheap or blocking. | Owner: the goal is a good baseline; adding modules is fine but wasn't the plan. They found C11–C13, C16, C17. |
| D23 | 2026-11-16 | **Compiled code borrows its globals; nothing may read them at compile time.** The globals dict is a compile-time constant but not owned (`vcompiler.c:PsycoObject_FromCode`, `ni_code_extra_t.entry_globals`), which breaks the cycle that kept code with its own globals alive (KNOWN_BUGS C14). This is safe only while compiled code uses the dict purely as an argument to run-time calls: a dead dict's address can be reused by a new dict, and old code then serves the new one. Anything that folds globals' contents at compile time (a cached LOAD_GLOBAL, generated code) must take its own owned reference, with a check that the value hasn't changed. On 3.12+ a dict watcher could drop code when its globals die (QUESTIONS 27). | Owner accepted (2026-11-16) | [read], [run] |
| D24 | 2026-11-16 | **Generated code is checked in, and `check.sh` fails if it is stale.** `ni/Objects/plongobject_gen.h` is written by `tools/metac/gen_long.py` from CPython's source. So building Ni needs no generator and no CPython source tree, a change to the generator shows as a diff of its output, and `tools/check.sh` reruns it with `--check` (CPython source at `NI_CPYTHON_SRC`, default the pyenv 3.7.17 tree). Generated files are never edited by hand. | `64f88e7` |
