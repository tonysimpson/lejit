| D42 | 2026-11-17 | **A promotion site is a polymorphic inline cache: the inline compare keeps its first value, and up to four more go in an out-of-line chain of compare/je cases in the stub pool** (`ff1bce8`, CODE_SIZE.md option 3, the owner's option B, as SpiderMonkey CacheIR and JavaScriptCore's polymorphic access stubs do). The site's miss path is overwritten with `jmp chain`, so the chain ends with its own miss stub or, once a site can compile no more values (the megamorphic cut-off), a `jmp` to the megamorphic version. A chain starts with room for one case and is copied to one with room for four when it grows. With no cut-off, a full chain's last case takes the newest value. Only the C dispatcher patches, and only code it will not return into; `je`/`jmp` only (D32). Nothing compiled depends on the cache, and replays never reach a promotion (D21).
