## Project and method
- **D1** Keep Psyco's design (run, compile and virtual time, promotion, merge points, virtual objects) as the template for the JIT.
- **D2** Fix maintainability by generating the compile-time CPython layer from CPython's C source with a meta-compiler, keeping Psyco's design rather than another route (meta-tracing, tracing JIT, copy-and-patch). The idea is Armin Rigo's, in `ni/Python/pycompiler.h`; GOAL.md.
- **D3** The phase is research and classification before new design.
- **D4** The source files are the source of truth; docs hold only what code can't say (goal, cross-file mechanisms, classification, judgement, references). No per-file prose summaries.
- **D5** Superseded by D9.
- **D6** `doc/MAP.md` is the coverage ledger: one row per file, with the commit it was reviewed at.
- **D7** Upstream Psyco is git `9bd5834` in this repo's history; nothing is vendored.
- **D8** Docs are local Markdown in `doc/`, British English, claims marked [read] or [inferred], anchored to `file:function`, not line numbers.
- **D9** Comments only where the code is complex: core, virtual-object, backend and translation files get a comment written for that file (the non-obvious, the traps, known bugs); simple files none; no templated headers.
- **D16** Long-term aim: a core with no coupling to Python, and a meta-compiler that consumes any CPython source and generates the whole Python layer, including the bytecode compiler, failing loudly on an incompatible change (GOAL.md).
- **D17** Target CPython 3.12+ (`Python/bytecodes.c`); 3.7 is the reference implementation.
- **D18** 3.7 baseline, time-boxed: fix core and backend bugs; translated-layer bugs are logged in KNOWN_BUGS and worked around, except minimal fixes that unblock testing of the core. Branch `baseline-3.7`.
- **D19** Start the meta-compiler simply, in stages: 0 field descriptors and layouts from the headers (done, D76); 1 token-level rewriting of a small slice; 2 analysis only where rewriting demonstrably fails (D74).
- **D20** Simplest tool that works: token-level rewriting in Python first, pycparser or Coccinelle only on real failure, clang last; log each failure in METACOMPILER.md.
- **D21** Guardrails as we go: every fix adds the check that would have caught it (a test failing without it, shown with `tools/without_fix.sh`, an assertion, or a tool check), and `tools/check.sh` runs before commits. Relaxed by D27.
- **D22** CPython's own tests (`tests/cpython_tests.py`) are a regression check, not a target; core and backend bugs they find are fixed, translated-layer ones logged.
- **D27** While chasing performance, each change gets a release build and the relevant `tests/run.py -k` cases; full `check.sh` every few commits and at milestones, and a failing-without-fix demonstration only for subtle bugs. Relaxes D21.
- **D28** Debug with pointbreak scripts in `tools/nianalyser` (`crash_report.py`, `dump_function.py`), not gdb (Ni never changes pointbreak).
- **D29** Compile speed comes first and there is no IR: every backend change is measured against compile time as well as run time, and when in doubt compile speed wins.
- **D34** Phase before generation: a robust 3.7 baseline with worthwhile performance work, each change measured against speed, compile time and code size, its pattern recorded in PATTERNS.md.
- **D64** Tony took every recommendation of GOAL.md's point-2 sweep. Accepted for 3.7: C9, C17 remainder, C19, C20, F72. C14, C15 remainder, C18, F27 remainder and option D are done on 3.7 (Tony, 2026-11-18, reversing their move to 3.12). Kept: F57's `__code__` guard, D60's version tag, D63's type hints.

## Compilation strategy
- **D10** Merge points by control flow, not on every instruction (`27f066d`), and inlining by upstream's rule (`085392a`, with B6).
- **D11** Bring back compact objects (fast instance attributes), keeping the old design but clearer.
- **D12** Compile everything on first call, with no hotness threshold or profiling (Tony, 2026-11-18): compile cost must be made small, not hidden, and compiling everything keeps it visible in every measurement.
- **D13** Floats, and integers as a virtual one-word int following CPython's one-digit fast paths, falling back to `PyLong` (`fdbaa88`); generated since D83.
- **D14** Python 3 `bytes` and `str` (PEP 393) are a goal; Py2's `pstringobject.c` is the design reference, not code to port.
- **D15** Dead-local deletion restored with a 3.7 liveness pass in `mergepoints.c`, and the `CodeBuffer_Check` guard in `psyco_compatible` (`458ef80`).
- **D23** Compiled code borrows its globals (`ni_code_extra_t.entry_globals`); anything that folds their contents at compile time must own its value and check it is unchanged (D25). C14.
- **D25** LOAD_GLOBAL is a constant behind the globals' and builtins' `ma_version_tag` guards (`pycompiler.c:load_global_cached`, `7a3a109`); nothing before a site's respawn point may depend on the dicts, and each guarded site ends its block (`split_after_global`). 3.12: QUESTIONS 29.
- **D30** Attribute lookup is specialised on the type behind a per-site `tp_version_tag` guard, and compiled code holds every descriptor it specialised on while it lives (`pobject.c:generic_getattr`, `d70e7f7`).
- **D31** Instance attribute loads are inline on the class's shared keys (`pobject.c:instance_dict_get`, a per-site `keys_guard_t`, keys held); a decision a replay must repeat may depend on one-way state through `codemanager.h:psyco_block_serial` (`keys_inline`).
- **D32** Respawn stubs are 15 bytes in pooled chunks with one shared trampoline and heap records (`dispatcher.c:psyco_new_stub`, `2f8d00f`); coding pauses (`d51860c`) and promotion miss paths (`85aabc2`, `psyco_new_stub_at`) use them too. Rule: compiled code never enters shared code with a `call` it doesn't return from.
- **D33** At merge points a counter has one form: `dispatcher.c:canonical_int` rewrites a local's small int or bool constant as a virtual int, and a known value may partially match a run-time one (`compatible_vinfo`; `1c61916`, `5e37663`).
- **D35** Inline dict stores take version tags from Ni's own counter, starting at 2^63, since CPython's is a static in `dictobject.c`.
- **D36** A METH_FASTCALL builtin without a meta is called directly through `cimpl_fastN` (N ≤ 5; `pmethodobject.c:PsycoCFunction_CallFast`); keywords stay `PyCFunction_Call`; a meta registers only under the convention it was written for, others listed by `ni._unregistered_metas()` (F13).
- **D37** str is read inline only where its layout is known while compiling (compact ASCII at run time, or a compact constant); anything else is a C call on a respawned branch, and one-character results are CPython's cached strings (`punicodeobject.c`, `9abd6a3`). Virtual characters: QUESTIONS 40.
- **D38** Inline attribute stores (FINDINGS.md "Attribute stores" option 4): one cache per (class, name), overwrite or fill-next-slot inline, combined dicts via `_PyDict_SetItem_KnownHash`, a cache stops refreshing after 64 misses; about 20–25% more code on richards accepted for about 13% speed. Built as D47.
- **D39** Attribute stores on heap types are behind a type guard shared per (type, name, kind) and repaired at run time (`pobject.c:store_kind`, `store_guard`, `cimpl_store_type_changed`; `e86f8ae`).
- **D40** After 6 blocks at a merge point (`MP_BLOCK_CAP`), the known values of ints and bools in locals are forgotten before comparing again (`vcompiler.c:mp_capped`, `dispatcher.c:psyco_forget_int_values`; `932f416`).
- **D41** From a merge point's second block, a large int constant in a local becomes a run-time object (same object); virtual values are not computed to match run-time ones (`dispatcher.c:psyco_unpromote_large_ints`, `e823ee8`).
- **D42** A promotion site is a polymorphic inline cache: the inline compare keeps its first value, up to four more in an out-of-line compare/je chain in the stub pool, then the megamorphic version (`ff1bce8`).
- **D43** Past the cap, a constant local that some block doesn't hold is made run-time and flagged `RunTime_Megamorphic`, and every promotion with a generic path takes it for a flagged value (`61db667`, SPECIALISATION.md rules 2 and 3). Kept as a backstop.
- **D44** A branch respawned from a split site's checks joins the main path's block after the site, through join points (`mergepoints.c:psyco_join_point`, `vcompiler.c:psyco_compile_join`, `f229d14`); the main path takes only exact matches. Restrictions lifted by D49.
- **D45** Compiled code tests `eval_breaker` before every backward-jump target, after `CALL_*` (narrowed by D53) and in `NiCode_Run`, with a respawn to `pyruntime.c:ni_eval_breaker_handler` when set (`e26c2a3`, C24).
- **D46** Each direct compiled call, inlined frame entry and fused generator expression tests the thread's `use_tracing` and, when set, makes the real call, run interpreted by the eval hook (`psyfunc.c:tracing_on`, `cf692d5`, C23). Off under `ni._set_trace_fallback(False)`.
- **D47** Option 4 (D38) as built, then its store sites shrunk: one hand-allocated emitter, failed checks call one out-of-line helper (`cimpl_store_miss`), shared glues for dealloc and miss, a 47-byte type-guard emitter (`80a60ce`, `4398496`, `035ef12`, `2606291`). Checks shared between consecutive stores not built.
- **D48** Mutable state a compile folds (heap-type slots `Psyco_HeapSlot`, function defaults `compiled_defaults`) is recorded as first seen, never updated, held, and compared with the live value at run time; a mismatch takes the generic CPython call for good (F50, F52).
- **D49** Join points match as merge points do (drop any known field, `canonical_int`, un-promotion in inlined frames), beyond D44's exact-only main path (`6f2c227`, after C27 and C28).
- **D50** A merge point drops a run-time value's known type that nothing since the last merge point relied on (`source_known_t.used` against `PsycoObject.mp_serial`), if no block matches without dropping; never in a promotion's own compare (`96b9777`, SPECIALISATION rule 1). Widened by D57.
- **D52** A frame's builtins are a compile-time slot `LOC_BUILTINS`, chosen as `frameobject.c` chooses `f_builtins` (`5f8b506`, F49; rest F72).
- **D53** After a call, `eval_breaker` is tested only if the call emitted a C call that may block (`po->blocking_call`; `CfNoBlock` or `psyfunc.c:psyco_cannot_block`), as part of the `CALL_*` instruction (`889fce6`).
- **D54** D48 covers every slot compiled code folds for a heap type (truth, numbers, subscripts, `len`, `in`, calls, `nb_index`, operand order) via `Psyco_TypeSlot`/`Psyco_TypeIsSubtype`; a changed slot resumes CPython's algorithm where the compile was (`d16ab6b`..`4a0d275`, F56, PATTERNS P29).
- **D56** Slices are virtual: BUILD_SLICE makes a virtual slice, and str, bytes and list subscript metas unpack it into word bounds for one step-1 C helper (`psliceobject.c`, `b251646`); constant slices of constant str or bytes fold.
- **D57** Rule 1 (D50) drops any unused known field of a run-time value, not only its type (`0b808fa`, after C35).
- **D58** Compiled calls to closures are direct; a run-time closure is not promoted, only its code, with its cells loaded from `func_closure` and its globals required to be the caller's (`psyfunc.c:psyco_call_closure`, `0b46284`, F8); zero-argument `super()` is `pbltinmodule.c:psuper_noargs`. Inlined run-time-cell closures take a reference per cell, and nothing is inlined into itself (`a664895`, C49).
- **D59** After code that may assign `__class__` (`po->pr.class_unchecked`), known types that can change (heap types, ModuleType subtypes) are forgotten, not checked (`pobject.c:Psyco_ForgetClasses`, `56e5faf`, F55).
- **D60** Load guards are shared per (type, name, kind) and repaired at run time like D39's (`pobject.c:load_kind`, `load_guard`, `cimpl_load_type_changed`), and Ni gives a heap class with a metaclass the version tag CPython 3.7 withholds by mistake (`enable_version_tag`; `6cd0c26`, QUESTIONS 41).
- **D62** A constant whose class can be assigned stays a constant, but its type is known only behind a chain of run-time `ob_type` checks against the types recorded for it (`pobject.c:Psyco_ConstantType`, `3116d30`, F96); the fact is forgotten as D59's and at every block start.
- **D63** A type forgotten by D59 is learnt again by a guard against its old type (`vinfo_t.type_hint`, `Psyco_TypeHintGuard`), not a promotion; hints are never facts and are kept in snapshots (`17c3ed8`).
- **D66** A promotion site's megamorphic version is not one of its `MEGAMORPHIC_MAX` values, and an entry going there never evicts a compiled value (`dispatcher.c:lookup_count_previous_values`, `promotion_cache_add`, `a599bd2`, C54).

## Generation
- **D24** Superseded by D67 (2): nothing generated from CPython is checked in.
- **D26** Revised by D67 (5) and D69: the bytecode generator's back half takes 3.12's instruction DSL (`InstDef`s from CPython's vendored `cases_generator`); on 3.7 its input is `ceval.c` read into that form, and `bytecodes37.c` is gone.
- **D65** LLVM only as an assembler (`llvm-mc`) for machine-code templates such as the encoder (QUESTIONS 37); no LLVM IR. Whether template output is checked in (not covered by D67) is decided when it exists.
- **D67** One Ni source for every CPython version from 3.7, with no `#if` and no version number: (1) hand-written code never knows the version; (2) everything that mirrors CPython is generated at build time from the target's source, not checked in; (3) features live in the core or the generator's rules; (4) where Ni's own mechanism must differ, a detector reads the source and selects a snippet (D75); (5) 3.7–3.11 read `ceval.c` into the `bytecodes.c` form; (6) generate everything possible on 3.7, then 3.8 and on. METACOMPILER.md "Versions".
- **D68** Build-time generation: `tools/metac/generate.py --python EXE --out DIR [--src DIR]`, called by `setup.py`; the source is `NI_CPYTHON_SRC` or the sha256-checked release tarball (`tools/metac/cpython_sha256.txt`, cached in `~/.cache/ni/cpython/`); `PY_VERSION` must match; the target's installed `pyconfig.h`; generators under `NI_GEN_PYTHON` ≥ 3.10; a header is rewritten only when its text changes (`9eae61d`).
- **D69** The 3.7 bytecode front end is `tools/metac/ceval_reader.py`: each `TARGET` run symbolically over tokens, written in `bytecodes.c` syntax and parsed by the vendored parser; front end chosen by what the source has; general rules only; anything else refused with a kind; every effect checked against `dis.stack_effect` (`7b21dea`).
- **D70** "Same code" means: on one workload, for every (code object, instruction), the multiset of compiled copies as (entry kind, disassembly with addresses named) is equal between two builds (`tools/samecode.py`, `8b8ffea`, FINDINGS.md "Code size" "Same code").
- **D71** The generator's judgement is one data file, `tools/metac/policy_table.py`, keyed by CPython definitions with the token shape each was written for and items from a closed vocabulary; one rule is a `RULES` entry; `policy.py` checks it before every generation; effect flags are computed by `tools/metac/effects.py` (`e7fd745`).
- **D73** Oparg-dependent stack effects are read from `ceval.c` as linear forms in oparg, as 3.12's DSL writes them, checked against `dis.stack_effect` at 13 opargs; the back half generates arrays, conditions and passthrough, with no per-opcode table (`99d9b26`).
- **D74** General translation (D19 stage 2): `tools/metac/gen_abstract.py` (over `cparse.py`) translates a C function into a meta by binding times and fixed rules (P01, rule 1, D54 slots, P05/P06), resuming CPython's algorithm at run time where a value has no compile-time form; first on `abstract.c`; the only per-function facts are policy items and Ni's declarations (`1aa473c`).
- **D75** Version-dependent mechanisms: detectors in `tools/metac/mechanisms.py` answer questions about the target's source, `VARIANTS` maps answer tuples to `ni/mechanisms/<mechanism>/<variant>.h`, `generate.py` writes `mechanism_<name>_gen.h`; unlisted answers fail the build; unwritten variants `#error` (`36b5beb`).
- **D76** Stage 0: the CPython fields Ni relies on are `policy_table.LAYOUTS` (and `RUNTIME`); `tools/metac/gen_layouts.py` generates offsets, sizes and private structs with a `_Static_assert` per assumption, used through `vcompiler.h:CPY_FIELD` and friends (`ee76274`, `9869ad9`).
- **D77** The rest of the version-dependent mechanisms go through D75: eval_breaker (location and handler), current thread state, recursion count, exception state, the inline store's GC test (`f254b5d`).
- **D78** Loops in the general translator: a counted loop with a compile-time bound is unrolled; a length bound is asked of Ni's representation (`TYPES` `known_length`, `PsycoTuple_Load`); any other loop is CPython's, resumed at run time. A respawn resolves the flags' condition on replay and branch (F106) (`83131e1`, `9ce5ad4`).
- **D79** Branches and jumps in generated ceval cases: the reader writes 3.7's dispatching arms as 3.12 does (rule `singleton_test_generic_path`), and the back half uses step 4's condition-code and residual-call rules, a jump being the core macros `JUMP_IF_CC`/`JUMPED` (`a907150`).
- **D80** Virtual objects are generated from their constructors and `policy_table.TYPES` (`gen_virtual.py`: tuple, slice, bound method; list stays hand-written); a call of a virtual type's constructor in translated C is the virtual (`a6a687b`, `603363c`).
- **D81** Loops with error exits in generated ceval cases are unrolled by D78's rule, with C ints of the compiler; `BUILD_LIST_UNPACK`/`BUILD_SET_UNPACK` make one residual call per part, as ceval does (accepted) (`5c8a4fb`).
- **D82** `ceval.c`'s static helpers are inlined into generated cases (`ceval_inline.py`); their type tests use only what Ni knows, else a generated run-time copy of the arm (`pycompiler_copies_gen.h`); cell fields are read through Ni's descriptors (`4c57d97`).
- **D83** Number families from the general translator: an int's one-word form is a representation rule in `TYPES` (`word`, read by `gen2/types.py` and applied by `gen2/reps.py`), and `gen_long.py` is retired (`a0c8ea9`, `28ff76f`).
- **D84** Container slots from the general translator: a slot found in the type's initialiser gets binding times from `policy_table.SLOT_ARGS`, an object field is read through `TYPES` `descriptors`, a compile-time `switch` is the meta's (`5169c24`); the rest of the container and string families stays hand-written, each with its reason.
- **D85** Argument binding is generated from `ceval.c:_PyEval_EvalCodeWithName` as a C function the compiler runs (`gen_call.py`, `psyfunc_gen.h`); anything with no form returns -1 and the real call is made (F92); the rest of the call path, including `pmethodobject.c`'s dispatch, stays core (`e11f2a3`).
- **D86** Builtins from the general translator: which C function a builtin is comes from the module's method table (`gen_builtins.py`), how Ni calls its meta from `policy_table.METH_ARGS`, and argument unpacking is the policy item `unpack_arguments` (`58e52de`, `a8a9038`).
- **D87** C doubles in the general translator: a `double` representation in `TYPES`, runs of scalar statements copied into C helpers, static functions given a pointer or a function inlined (gen2's `scalar.py` and `inline.py`, for floats and math; `scalars.py` keeps the representation for gen_abstract's units); `gen_float.py` retired (`cddaf8d`, F99).
- **D88** Seven more opcodes generated: the core primitive `psyco_xdecref_rt`/`psyco_xdecref_v` releases a run-time value Ni holds no reference to, plus six general rules (`field_store`, `helper_copy`, `error_handler`, `residual_wrapper`, `switch_arms`, `type_test_generic`) (`fa3dae7`, `e33981f`).
- **D89** Conditional compilation is evaluated as CPython's build does (`preprocess_conditionals`), and str's length and `+`, member descriptors, `PyMember_GetOne` and `delattr` are generated by general rules (`bit_field`, `runtime_choice`, `raw_pointer`, `switch_break`) and policy items (`ccb5735`).
- **D90** GOAL's done test, point 1, is `tools/metac/donecheck.py`: it finds what mirrors CPython from the code and needs a reason for each hand-written one; written reasons live only in `tools/metac/hand_table.py`, checked against the code and docs (exit 2 stale, 1 unreasoned) (`88d850c`). Passing is necessary, not sufficient (D99).
- **D92** `CfNoPython` from the effect rules stays on generated calls, and `PyUnicode_Contains` is generated; an instruction count that moves only in libc's malloc, or flips sign under a heap perturbation, is not a cost of the change (PROFILE.md "Heap state") (`03ce514`).
- **D93** The iterators' `tp_iter`, `callable`, `hasattr` and `BUILD_TUPLE_UNPACK*` are generated by five general rules and the policy item `('virtual', 'concat')`; `iter`, `next`, `chr`, `ord`, `BUILD_CONST_KEY_MAP` and `IMPORT_NAME` stay, with reasons in `hand_table.py` (`9e58f97`…`18c250d`).
- **D94** The new front end's C parser is pycparser 3.11, vendored unchanged under `tools/metac/third_party/pycparser/` from PyPI's sdist (sha256 `d875f09c3507d00e1aba0eecc6dcadc1352f30fff09dc6bff2f1c2935e97c2bc`, checked against PyPI's published hash; BSD licence kept); `front.py` refuses any other version. Vendored, not installed, so the build doesn't depend on what the generating Python has installed and another release can't parse differently unnoticed; 3.11 rather than 3.12 because 3.12 needs Python 3.11 and the generators' floor is 3.10 (D68). Pure Python, like `cases_generator/` (D26) (`a3433b4`).
- **D95** The front end preprocesses with `-DUSE_COMPUTED_GOTOS=0`, its one departure from CPython's build flags: computed gotos (`&&label`, `goto *`) don't parse, and with them off `ceval.c`'s `TARGET`s are `case` labels of one `switch`. Every other flag is the target's own, from its sysconfig: `PY_CORE_CFLAGS`, or for a `Modules/` file `PY_BUILTIN_MODULE_CFLAGS` or `PY_STDMODULE_CFLAGS` by whether its module is built in, and its `pyconfig.h` (`front.py`, `ca8dbb5`).
- **D96** Effects are five flags per function, computed on the front end's AST of every file libpython links and every mirrored file; anything indirect or unread is the worst case, and a file that isn't mirrored and doesn't preprocess is left out as unread. `CfPure` needs pure, readonly, no Python and no raise; `CfNoBlock` follows no_block alone, so an `ASSUMPTIONS` no_block holds for a function that may run Python (`041bbd1`).
- **D97** The done check's reasons are final (`hand_table` kinds core, mechanism and judgement; not_mirror is no mirror) or transitional (limit, helper, a policy item, a generator's refusal of the counterpart); it passes only with no transitional ones, and `check.sh` accepts exit 3 (transitional only) until the phase is done (`ac8f978`).
- **D98** `generate.py` writes `report.txt`, a line per function (key, status, reason, location; keys name no file so versions diff), whose key, status and reason must equal the checked-in `tools/metac/expected/<version>.txt`, accepted by copying the report over it; donecheck reads it and refuses one from another source sha or generator commit (HEAD plus a hash of uncommitted changes) (`ac8f978`).
- **D99** (delegated by Tony, 2026-11-18) Done counts definitions. A helper called only by core definitions is core, so final. `gen_ceval`'s own "core" refusals stay transitional until the declared core list (GENERATOR_DESIGN `scope.py`) names them with a reason.
- **D100** (delegated by Tony) A rule may name a definition a version lacks; there it is reported `absent`, with no notation in the rule. 3.8's different block opcodes come from a header generated from the target's `Include/opcode.h`, not a hand-written mechanism.
- **D101** (delegated by Tony) D92 stands: a ~1% move counts as a regression only if it survives PROFILE.md's heap-state controls. D81 stands: one residual call per part, as ceval.
- **D102** Compiled code belongs to an owner, the record of the code object whose merge points it is registered at (an inlined callee's code is its caller's). Each owner holds its machine-code extents (a free-extent allocator replaces the bump allocator), its code buffers, its stub records, stub pool and guard records, and a set of the objects its constants refer to; `ni.c:ni_code_extra_free` releases them all, nothing on the hot path changes. A caller pins the code objects it calls or inlines and a callee pins the constants it was compiled with, so code that can still be reached is never freed under a caller. A cycle back to the code object (its own globals dict, through a cached global) is not broken: code objects aren't GC-tracked (`codemanager.c:psyco_owner_release`).
- **D103** Running out of memory mid-compile abandons the compile: each way into the compiler pushes a guard with `sigsetjmp`, and `OUT_OF_MEMORY` unregisters the blocks made under it and jumps back, leaving their memory to the owner unused. The first compile of a code object then runs the call interpreted; a pause, respawn or promotion compiles again from a state the compile didn't consume (a pause keeps a copy), since compiled code can't return to the interpreter. The guarded functions are out of line, so the calls that don't compile don't pay for `sigsetjmp` (`codemanager.h`).
- **D104** (delegated by Tony) The new translator is the package `tools/metac/gen2/` (its `types.py` and `policy.py` would otherwise shadow the standard library's `types` and the old `policy.py`); its modules are never run as scripts, and its tests live in `tests/`. The vocabulary shim is written from `gen2/vocabulary.py` into the cache, so there is one list.
- **D105** (delegated by Tony) A run-time copy is the function's source text, the file's own function-like macros expanded (Ni's file doesn't define them) and header macros kept; copies are numbered in the order the final walks make them, and only those a kept meta names are written. A report names a statement by its source text, macros as written.
- **D106** (delegated by Tony) gen2's policy items are typed objects keyed by function name, with a precondition checked against the AST and no shape hash; their `policy_table.ENTRIES` rows keep only `ni` for the done check, and `policy.py` accepts a gen2 row with no shape. An item the translator doesn't implement (`HandOnly`) names every such item in the refusal.
- **D107** (delegated by Tony) In gen2 a raise, or an error test that held, sets the path's error state; a run-time call there is refused (the exception would be set when it runs), as is a resume.
- **D108** (Tony agreed) The adversarial suite measures honestly rather than flatteringly: every call timed with no best-of, several fresh processes, three run lengths calibrated on CPython, training on one input and timing another, outputs compared in full, and losses counted before any mean, with failures scored as losses.
- **D109** The generation cache (preprocessing, ASTs, effects) lives in the user cache beside the CPython tarballs, not the build directory: every worktree and agent building the same CPython shares it, and it survives `rm -rf build`. Its keys hash every input, so sharing is safe; writes are atomic renames.
- **D110** (delegated by Tony) The numbers family is on gen2: `scope.Family` names a family's slots (the metas `gen_FILE_init` registers) and its representations, a static slot function's report key is `Type.slot`, and the representations stay data in `policy_table.TYPES` (its `word` and `double` sections, checked by `policy.py`). A pointer to any struct whose first fields lead to `PyObject` by `ob_base` is an object (`PyLongObject *`, through the anonymous `PyVarObject`).
- **D111** (delegated by Tony) A run-time branch with no `likely` item resumes when nothing has been called yet (CPython's whole function then decides it, as it would unspecialised), and is refused after a call.
- **D112** (delegated by Tony) A callee whose Ni name another of Ni's headers declares is Ni's own meta: calls use it and gen2 doesn't translate it (`PyLong_AsDouble`, `PyNumber_AsSsize_t`); a representation's constructors are never callees.
- **D113** (delegated by Tony) gen2's scalar helper: the rest of a block when every path returns, else the longest run leaving at most one live variable; it must read a double and do more than copy. A helper that may raise returns an `int` status and its result through a one-item output array (`CfCommonIntZeroOk`, `"a"`), never `CfPyErrCheck`; a run that is only a pure function of another file given the helper's parameters in order is that function, called directly.
- **D114** (delegated by Tony) gen2 inlines a static of the file only when the call passes a local's address, a constant or a function's name, and the body has no loop, switch or goto (a constant or name whose parameter is never assigned or addressed is substituted, so `(*func)(x)` is a direct call); its returns must be constants that choose the caller's branch, one that falls through only last. A resume inside an inlined body is refused (the copy is of the C as written). Budgets: 3 levels of inlining, 40 statements, 16 re-walks.
- **D115** (delegated by Tony) Math is on gen2: a family's `builtins` are read from its `PyModuleDef` method table (name, C function, `ml_flags`), only `METH_O` ones are translated (others are reported with their flags), and a resume before any call is the function called as Ni calls its flags. A static of the file that is itself scalar code (its own raises, errno set within it) is called inside a helper as its whole copy; `scalars.py` stays, for gen_abstract's remaining units.
- **D116** (delegated by Tony) list, dict, bytes and str slots are on gen2: an object's field with a `TYPES` descriptor is read through it, the struct being the outermost cast `TYPES` names, else the variable's type; a one-bit field and a `?:` on it are gen2's `bit_test` and `Walk.choice`. Two policy items: `FoldMayFail` (call CPython while compiling on constant objects, its error left to run time) and `Whole` (call the function whole: `PyUnicode_Concat`, which compiled would only add guards before calling CPython's copy).
- **D117** A frame running compiled code when tracing or profiling starts goes on in ceval: after each `CALL_*` that emitted a call that may run Python (`po->pr.python_call`), and at each handler entry, compiled code tests `use_tracing`; the rare path copies the locals, value stack and blocks into the real frame or a new one and resumes ceval after the instruction, as for a generator, with the frame's 'call' event skipped (`pycompiler.c:resume_if_tracing`, `frames.c:psyco_resume_run`, C29). Only calls are tested, not every instruction that may run Python, for the cost.
- **D118** A compiled frame writes its locals into its traceback entry's frame when an exception passes it, and keeps a real frame's borrowed entry locals alive (`pycompiler.c:traceback_locals`, `frames.c:psyco_frame_write_locals`, C18). Not when the innermost handler is `except E: pass` or `except: pass`, which drops the exception unseen, for the cost (deepcopy's `KeyError`); a mismatching `E` re-raises at END_FINALLY, which writes them then. Only an `E` whose `__subclasscheck__` reads `sys.exc_info()` could tell.
- **D119** Compiled frames as Python and C code see them (C11): `frame.f_back` and `frame.f_lineno` are replaced in `PyFrame_Type`'s dict by getters that read Ni's frame chain (`frames.c:frame_get_back`, `frame_get_lineno`), so a real frame entered through C from compiled code keeps the `f_back` ceval gave it, which the evaluators put `tstate->frame` back to, and costs nothing until read. Relinking it instead, at entry or when something looks, needed the eval hook to put `tstate->frame` back after every frame and cost 1.1–1.6% (hexiom, raytrace); setting `tstate->frame` around residual calls would cost a frame per call. A traceback frame gets the entry over it as `f_back`, and the one for the catching frame its caller, noted cheaply in its empty value stack and found when read (eagerly it cost deepcopy 19%). Emulated frames get their line from where the next frame in was called, recorded per call site, and the innermost one from the note in its finfo slot (D131). C code that reads `f_back` or `f_lasti` itself bypasses the getters: `_warnings.warn` is wrapped to run with every frame linked and placed (`frames.c:ni_warn`).
- **D120** Finalisers run in CPython's order: a returning compiled function releases its locals first to last, as `frame_dealloc` (`pycompiler.c:exit_function`), and a dead virtual's run-time parts are kept in their order so the array releases them last to first, as `list_dealloc` and `tupledealloc` (`pobject.c:Psyco_SafelyDeleteVar`). Other releases of virtual arrays keep Psyco's last-to-first order.
- **D121** (Tony, 2026-11-18) Correctness comes before speed: a fix for wrong visible behaviour is merged even if it costs over 1%, after a real attempt at a cheaper design; the cost then becomes speed work. First applied to C11's `f_back` through C.
- **D122** (delegated by Tony) An owner holds each constant from when its `source_known_t` is made (`vcompiler.h:sk_new`), and per-address guard records are objects each owner that used one pins (`codemanager.c:psyco_record`), so everything code relies on is in its owner's set. Cycles through code objects, which CPython's GC can't see, are found by trial deletion over owners (`codemanager.c:owners_scan`), seeded from the functions `gc.get_objects` lists. A record is counted when its owner first holds a reference; once the count since the last scan reaches half the live ones (at least 512, above the 277 the largest pyperformance benchmark makes), the scan is queued as a pending call (`Py_AddPendingCall`), so short programs never scan, and dead records stay bounded (exec'd namespaces calling each other: +10 MB at most, flat from 2000 to 48000) [run]. A full collection also scans if a record was counted since the last, so `gc.collect()` frees such cycles as CPython would (`test_module`): through a `gc.callbacks` entry listed only once the program has imported `gc`, as any caller of `gc.collect()` has, and only while there are new records. Ni doesn't import `gc` itself: at start-up that ran importlib's Python code under Ni, which compiled it, about 1% of a short benchmark's cold run [run]. The cost left is the scans themselves where a program calls `gc.collect()` (gc_collect, cold +1.8%) [run].
- **D131** (delegated by Tony) A compiled frame's locals as Python sees them (C15): before each residual call that may run Python, one store puts in the frame's finfo slot a note naming a map, made at compile time, of where each local is during that call: a stack slot, a constant, a virtual value's parts (if `direct_compute_fn` can rebuild it), or a callee-saved register (`codegen.c:psyco_locals_map`); a compiled callee's record carries the map of its caller's at that call. `frame.f_locals` (replaced in `PyFrame_Type`'s dict) and emulated frames, when first asked, rebuild the values (`frames.c:slot_locals`); registers are found by unwinding the C frames above the call with libunwind, stepping over each nearer run of compiled code from where its glue saved them, and the call's return address tells a stale note, so nothing is stored after the call. Costs (instructions, N=20): within ±1% everywhere, nbody +0.95% the most, as the note replaces C11's two stores before and after each `CALL_*`. Pushing each register-only local to the stack instead cost chaos +1.3% at `CALL_*` sites alone and up to 4.8% (unpack_sequence, spectral_norm, nbody) at every call; a store before and a clear after every call cost up to 3.8%. Code naming `locals`, `vars`, `dir`, `eval` or `exec` stays interpreted (`mergepoints.c`); reached by another name, a meta makes the caller's virtual locals real and runs them with its frame emulated and current (`frames.c:cimpl_with_frame`).
- **D123** (delegated by Tony) Sanitizer builds (`NI_SANITIZE`) go only into `build/asan`, with their own config stamp, so they never replace the in-place module check.sh tests; CPython stays uninstrumented (libasan preloaded, `PYTHONMALLOC=malloc`), and under ASan Ni's pool allocators give each item its own malloc block rather than poisoning by hand, which gets ASan's quarantine and allocation stacks for free.
- **D124** (delegated by Tony) gen2's meta loops: a counted loop to a meta bound is unrolled when Ni compiles, with an unroll budget of 16 turns, above `CT_TUPLE_LOAD_SIZE_LIMIT`. Past the budget, CPython's code runs from the loop: a known length over it counts as unknown at its load, and any other bound is checked before the loop. Nothing resumes inside a meta loop. A promotion a turn needs after a call is made at the outermost loop's entry if nothing was called before it, else at the function's entry for a parameter, and refused for items. Loops are keyed by their place in the function.
- **D125** (delegated by Tony) Tuples are on gen2 as the `known_length` representation (`TYPES`' `known_length` and `virtual` sections). A `PyTuple_New` of a meta size is Ni's virtual, not a callee. A store of a borrowed item must be followed by the C's own incref of it. A resume while a virtual is half built is refused unless it is an at-once restart, which releases it. The new policy item is `IfKnown(n)`: a count is its compile-time value, else CPython's function runs, with no promotion. Slot parameters take their binding times from `SLOT_ARGS`.
- **D126** (delegated by Tony) The builtins are on gen2. A `METH_FASTCALL` function's arguments are one tuple whose count is a constant per path: at the top-level statement holding a check of the count (`gen2/conventions.py:ARGUMENT_CHECKS`, by parameter position, names checked where the declaration has them), the rest is walked once per count within the check's bounds, at most 5 (budget `polyvariance`), and CPython's function runs outside them; no other statement may read the count first. The facts the old generator kept as policy items stay there and gen2 reads them (`zero_or_one`, `bool_word`, `null_arg`), so the done check's reasons and the hand metas they describe keep one source.
- **D127** (Tony, 2026-11-18) Ni always follows CPython's visible behaviour, including object identity CPython happens to give (so F117 is fixed: a folded float is boxed afresh each time it escapes). Behaviour Python doesn't promise may differ only in a future fast mode, as PyPy differs (it defines `is` and `id()` of floats and ints by value).
- **D128** (delegated by Tony) A code object's record is held by a weak reference of Ni's own type on the code object (`ni.c:ni_code_extra`), not by a `co_extra` slot. On 3.7 a subinterpreter's `co_extra` free functions are never initialised, and its collections free the main interpreter's garbage too, but a weak reference's callback runs in any interpreter (C57's fix). The reference isn't GC-tracked. `weakref.getweakrefs` on a code object Ni has seen lists it, in the same way that `sys.getrefcount` already differs under Ni. Finding it walks `co_weakreflist`, which is no slower than `_PyCode_GetExtra` (warm and cold within ±0.4% on six benchmarks; unpack_sequence over 3000 iterations +0.01%) [run].
- **D129** (delegated by Tony) The compiler state a coding pause or a promotion site keeps is parked (`dispatcher.c:psyco_park`): live for the 4096 newest (`PARK_LIVE_MAX`), then frozen into a snapshot's pseudo-code with the fields a snapshot rebuilds or leaves out saved beside it, and the promoted variable as a path of indices. Live states were 43% of the heap per code buffer. Freezing every state at once cost 2.8–3.2% of cold instructions on deltablue and hexiom (compressing, then freeing the live copy, for states mostly used soon after). With the window, no pyperformance benchmark freezes one, while large programs freeze nearly all [run]. Freezing keeps what is known of constants' classes, unlike `fpo_build`, so a frozen state compiles the same code as a live one (the same code bytes on `tools/memrepro.py`) [run]. A state with a pending pseudo-exception stays live, as does one whose promoted variable is under a constant or more than 6 levels deep.
- **D130** (delegated by Tony) A result built at compile time from constants (a `CfPure` call returning an object, a forced virtual whose fields are all constants) stays a constant only if it has another reference, i.e. CPython would share it too (a small int, a cached one-character str, the empty tuple, the operand itself); a fresh object is released and its constructor emitted, so each run makes one (`vcompiler.h:psyco_shared_constant`). The computation still folds: the virtual's fields stay known after it is boxed.
- **D132** (delegated by Tony) Argument binding is on gen2 as an entry of its own (`gen2/binding.py`). It shares the front end, typing, the C builder, the vocabulary and the `known_length` representation with the walk, but not the walk itself: everything in it is a C value of the compiler or an array of vinfos, and its one action for anything else is a restart (`return -1`), not a residual call or a resume. The keyword parameters leave Ni's declaration; `gen2/conventions.py:BINDING` gives them the values Ni's call passed (no keywords, no `kwdefs`), which fold, so the keyword path isn't generated, and a read of one on a path that runs is refused. Ownership is checked: no restart, overwrite or end while a local holds a reference.
