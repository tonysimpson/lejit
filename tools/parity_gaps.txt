# The version gaps tools/parity.py knows: where CPython's interpreter
# (ceval) runs a construct's code on some versions and LeJIT runs it
# compiled on others. CI fails on a gap missing from here, and on one listed
# here that has closed, so this list is always what main does now.
#
# construct (as parity.py names it) | versions | why
generator in a for loop | 3.11+ | every generator is made by ceval's RETURN_GENERATOR; 3.7-3.10 make it in C
yield in try/finally | 3.11+ | made by ceval's RETURN_GENERATOR, as every generator
yield in with | 3.11+ | made by ceval's RETURN_GENERATOR, as every generator
yield from | 3.7-3.10 | a generator using yield from runs in ceval: YIELD_FROM in a generator isn't compiled there
yield from | 3.11+ | the inner generator is made by ceval's RETURN_GENERATOR
generator with 70 locals | 3.7-3.10 | resumes run in ceval: a resume copies at most 64 words through the C stack
genexpr into any() | 3.14+ | CPython turns any(genexpr) into a loop over a real generator, so it isn't fused; the generator is made in ceval
genexpr into list() | 3.15+ | as any(): CPython makes list(genexpr) a loop over a real generator
coroutine awaited at once | 3.11+ | every coroutine is made by ceval's RETURN_GENERATOR; 3.7-3.10 start one with no object
coroutine that pauses | 3.7-3.10 | once a coroutine pauses, the rest of its life runs in ceval; 3.11+ resume it compiled
async with, left by return | 3.7 | 3.7's finally blocks use a pseudo-exception no ceval frame can hold, so the coroutine isn't compiled
async with, left by return | 3.11+ | the coroutines are made by ceval's RETURN_GENERATOR
async for | 3.11+ | __anext__'s coroutines are made by ceval's RETURN_GENERATOR
async generator | 3.11+ | the coroutines are made by ceval's RETURN_GENERATOR (async generators are in ceval on every version)
locals() in a list comprehension | 3.12+ | CPython inlines comprehensions, so the whole function names locals() and isn't compiled
yield in except | 3.7-3.10 | the handler's blocks and exception triple live outside the frame there, so a generator that yields in a handler runs in ceval; 3.11+ keep them in the frame and compile it
